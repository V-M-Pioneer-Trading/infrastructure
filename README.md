# V-M-Pioneer-Trading — infrastructure

Terraform for the V-M-Pioneer-Trading SpaceTraders backend services. Each service
is a small Terraform stack in its own directory; together they run as Docker
containers on a **shared EC2 host** that is owned and managed in a separate
repository ([`mradomsky/infrastructure`](https://github.com/mradomsky/infrastructure),
private). That repo also owns the account-wide primitives — the VPC, the shared
host, the CloudFront distribution that fronts these services, the Terraform state
bucket, and the CI OIDC providers. Read its
[`docs/security-model.md`](https://github.com/mradomsky/infrastructure/blob/main/docs/security-model.md)
for the account's overall security posture.

## Stacks

| Directory | What it manages |
| --- | --- |
| `navigation-service/` | navigation-service container, its encrypted EBS data volume (SQLite at `/data/nav.db`), daily EBS snapshots, and the **single shared security-group ingress rule** all backends sit behind. |
| `agent-service/` | agent-service container + its MySQL sidecar (encrypted EBS, daily snapshots) and the `st-gateway` container. DB passwords are generated by Terraform and stored as SSM `SecureString`. |
| `fleet-service/` | fleet-service container. |
| `automation-service/` | automation-service container + its Postgres sidecar (encrypted EBS, daily snapshots). DB password stored as SSM `SecureString`. |
| `caddy/` | The Caddy edge proxy — the single service CloudFront reaches. Terminates TLS on 443 (Let's Encrypt via ACME DNS-01), routes each `/api/<service>/*` path to its container on localhost, and enforces the `X-Origin-Verify` origin secret. |
| `ci-deploy-role/` | The shared `github-actions-ssm-deploy` IAM role each service repo's CI assumes (via GitHub OIDC) to trigger a redeploy through SSM. |

Each stack reads the shared host's details (instance ID, IAM role name, security
group ID) from the personal remote state at `personal/terraform.tfstate`, so it
never re-creates account-level resources.

## How a service reaches the internet

There is no public ingress to the containers. The security group admits **only**
AWS's `com.amazonaws.global.cloudfront.origin-facing` managed prefix list, on port
**443 only**, so the host cannot be reached directly by anything that resolves the
Elastic IP. Traffic arrives through the CloudFront distribution (defined in the
`mradomsky/infrastructure` spacetraders stack) as a single **HTTPS** origin, which
the `caddy/` edge proxy terminates and routes by `/api/<service>/*` path to each
container on localhost. Administrative access is via **SSM Session Manager**;
there is no open SSH port, and **IMDSv2 is required** on the host.

Two properties the prefix list alone could not provide, both now enforced by Caddy
(see [`caddy/README.md`](caddy/README.md)):

- **Encryption in transit.** CloudFront→origin is TLS, so the forwarded
  `Authorization` header is no longer plaintext on the wire.
- **Origin authentication.** The prefix list covers *all* of CloudFront, so any
  AWS customer's distribution could otherwise reach the host. Our distribution
  injects a shared secret as the `X-Origin-Verify` header; Caddy returns 403 to
  anything without it.

## Deployment model

Terraform provisions the EBS volumes, IAM policies, and an **SSM Command document
+ association** per service. The association runs a bootstrap script on the host
that: waits for cloud-init, formats/mounts the attached data volume (idempotent),
installs Docker, reads any DB password from SSM Parameter Store with
`--with-decryption`, and `docker run`s the container with `--network host`.

Application redeploys are triggered from each service repo's CI, which assumes
`github-actions-ssm-deploy` (see `ci-deploy-role/`) and issues `ssm:SendCommand`
against the bootstrap document — no long-lived AWS keys involved. Because service
images are pulled by tag at bootstrap time, the app image variables default to
`:latest` (CI drives the actual version); the database sidecars are pinned to a
major version so a host rebuild cannot silently upgrade the on-disk format.

## State

All stacks use the shared S3 backend (`radomskyi-tfstate`, versioned + encrypted)
with native S3 lockfiles (`use_lockfile = true`), each under a distinct key. No
state lives on any workstation.

## Secrets

No secrets are committed. `.gitignore` excludes every `*.tfvars`; non-secret
values (e.g. the state bucket name) are passed at apply time. Database passwords
are generated with `random_password` and written to SSM as `SecureString`; the
host reads them at container-start. The private GHCR pull token is created
out-of-band with `aws ssm put-parameter` and never enters Terraform state. The DB
passwords are instead generated by Terraform (so their values do land in the
private, encrypted state); moving them to the same out-of-band pattern is tracked
in [#23](https://github.com/V-M-Pioneer-Trading/infrastructure/issues/23).

## Local commands

```bash
terraform -chdir=<stack> fmt -check -recursive
terraform -chdir=<stack> init -backend=false
terraform -chdir=<stack> validate
```

CI (`.github/workflows/terraform.yml`) runs the same `fmt` / `init -backend=false`
/ `validate` across every stack on each pull request. It holds no AWS credentials.
